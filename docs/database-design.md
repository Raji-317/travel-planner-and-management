# Database Design & Schema Documentation

The relational database `travel_planner_db` is designed in Third Normal Form (3NF) to ensure integrity, reduce redundancy, and enable transaction-safe concurrency.

## 1. Relational Entities Summary

1. `users`: Stores user identity, cryptographic PBKDF2 hash, salt, and role (`TOURIST`, `OPERATOR`, `ADMIN`).
2. `operator_profiles`: Extends user records for licensed operators.
3. `destinations`: Destination cities, coordinates, daily budget estimations, and ratings.
4. `attraction_categories`: Taxonomy of attractions (Adventure, Beach, Nature, Heritage, etc.).
5. `attractions`: Specific points of interest, durations, ticket pricing, opening and closing hours.
6. `attraction_distances`: Graph adjacency list storing distances (km), travel times (min), and transit fares.
7. `packages`: Tour packages authored by operators.
8. `package_itinerary_days`: Day-wise activities and inclusions for packages.
9. `package_departures`: Scheduled travel dates with seat inventories and atomic constraint `CHECK (available_slots >= 0)`.
10. `bookings`: Reservation records with booking reference (`BK-YYYY-XXXXXX`).
11. `booking_travelers`: Passenger manifests.
12. `payments`: Simulated payment transaction logs.
13. `cancellations`: Cancellation requests and simulated refund records.
14. `reviews`: Tourist reviews with unique constraint preventing multiple reviews per user/package.
15. `saved_itineraries`: Customized plans generated by the Smart Planner.
16. `itinerary_days`: Day-by-day itinerary schedule.
17. `itinerary_places`: Time-slotted visits with transit times to the next stop.
18. `wishlist`: Bookmarked destinations and tours.
